# Decky Mihomo

`Decky Mihomo` — это плагин для `Decky Loader` на `Steam Deck`, который позволяет:

- добавить `Clash/Mihomo`-подписку прямо из `Game Mode`;
- запускать `mihomo` как системный VPN через `TUN`;
- переключать ноды и локации из игрового режима;
- проверять доступность серверов;
- собирать диагностику, если VPN поднялся, но трафик не пошёл.

## Как теперь устроена установка

Для настоящего системного VPN на `Steam Deck` одного только Decky-плагина недостаточно: `mihomo` нужен доступ к `TUN`, маршрутам и сетевым правилам. Поэтому проект теперь использует схему из двух частей:

1. сам Decky-плагин в `Game Mode`;
2. одноразовый `helper` для `Desktop Mode`, который ставит `root systemd`-сервис.

Это делается один раз. После этого подключение, отключение, обновление подписки и переключение нод работают уже из `Game Mode`.

## Установка на Steam Deck

### 1. Установи плагин

Поставь плагин через `Decky Loader` обычным способом:

- из `GitHub Release` zip-архива;
- или из локального zip, если твой Decky это поддерживает.

### 2. Один раз установи helper в Desktop Mode

После установки плагина перейди в `Desktop Mode` и выполни:

```bash
sudo bash /путь/к/папке/плагина/scripts/install_steamdeck_helper.sh
```

Если ставил плагин из репозитория, путь обычно будет в папке плагина `Decky`. Точную команду плагин показывает в своём UI в блоке `Helper`.

Что делает этот скрипт:

- создаёт стабильную папку данных для плагина;
- ставит `systemd`-unit для `mihomo`;
- добавляет `sudoers`-правило, чтобы Decky мог безопасно управлять сервисом без пароля;
- перезагружает `systemd daemon`.

После этого перезапусти `Steam` или `Decky Loader`.

## Как пользоваться в Game Mode

1. Открой `Decky Mihomo`.
2. Убедись, что в блоке `Helper` написано, что helper установлен.
3. Открой страницу ввода подписки.
4. Вставь ссылку на `Clash/Mihomo`-подписку.
5. Нажми `Сохранить и обновить подписку`.
6. При необходимости выбери группу и ноду.
7. Нажми `Подключить VPN`.

## Что поддерживается

Плагин рассчитан на профили формата `Clash/Mihomo YAML`, включая типичные подписки с:

- `proxies`;
- `proxy-groups`;
- `rules`;
- `VLESS`-нодами внутри `Clash/Mihomo`-профиля.

Важно: ссылка должна отдавать именно `Clash/Mihomo YAML`, а не просто набор `vless://...` ссылок.

## Диагностика

Если VPN формально запускается, но трафик не идёт:

1. открой в плагине раздел `Диагностика`;
2. нажми `Обновить диагностику`;
3. пришли содержимое `summary`, `Mihomo log` и `Сетевой снимок`.

Плагин сохраняет диагностику в отдельный `diagnostics.txt` и маскирует чувствительные данные вроде `uuid`, `secret` и URL подписки.

## Релизы на GitHub

В репозитории настроен `GitHub Actions` workflow, который собирает релиз по тегу `v*`.

В релизный архив попадают:

- `dist/index.js`
- `dist/index.js.map`
- `main.py`
- `package.json`
- `plugin.json`
- `README.md`
- `LICENSE`
- `scripts/install_steamdeck_helper.sh`
- `bin/`, если в репозитории лежит готовый бинарь

## Как выпустить новую версию

1. Обнови версию в `package.json`.
2. Собери фронтенд локально:

```bash
npm install
npm run build
python -m py_compile main.py
```

3. Закоммить изменения и отправь тег:

```bash
git add .
git commit -m "Release vX.Y.Z"
git push origin main
git tag vX.Y.Z
git push origin vX.Y.Z
```

После пуша тега `GitHub Actions` создаст новый `Release` и приложит zip-архив.

## Безопасность

Никогда не публикуй в репозитории:

- реальную ссылку подписки;
- рабочие `uuid`;
- `short-id`, `secret`, приватные токены;
- экспорт `YAML` с живыми ключами.

## Основные файлы проекта

- `main.py` — backend Decky-плагина
- `src/index.tsx` — UI для `Game Mode`
- `scripts/install_steamdeck_helper.sh` — одноразовая установка системного helper
- `scripts/package_release.py` — упаковка релизного архива
- `.github/workflows/release.yml` — публикация релизов на GitHub
