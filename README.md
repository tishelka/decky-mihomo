# Decky Mihomo

`Decky Mihomo` это плагин для `Decky Loader` на `Steam Deck`, который позволяет:

- добавить ссылку на `Clash/Mihomo`-подписку прямо из игрового режима;
- при необходимости вручную вставить `YAML`-профиль;
- запускать `mihomo` в `TUN`-режиме, чтобы VPN работал на уровне системы;
- проверять доступность нод;
- быстро переключаться между серверами и локациями прямо в `Game Mode`.

## Что поддерживается

Плагин рассчитан на профили в формате `Clash/Mihomo`, похожие на экспорт из `Koala Clash` или `Clash Verge`.

Поддерживаются профили, в которых есть:

- `proxies`
- `proxy-groups`
- `rules`
- ноды `VLESS` внутри `Clash/Mihomo YAML`

Важно: сейчас плагин ожидает, что ссылка подписки возвращает именно `Clash/Mihomo YAML`, а не список `vless://...` в `base64`.

## Как это работает

1. В игровом режиме ты вставляешь ссылку на подписку в интерфейс плагина.
2. Плагин сохраняет ссылку локально на `Steam Deck`.
3. Затем он скачивает профиль и кладет его в директорию настроек Decky.
4. При первом запуске плагин скачивает совместимый бинарник `mihomo`, если он еще не лежит в `bin/mihomo` и не установлен отдельно в системе.
5. После этого плагин запускает `mihomo` со своим управляемым конфигом.
6. Плагин получает список групп и нод через локальный `controller API`.
7. По кнопке можно проверить задержку серверов и выбрать лучшую доступную ноду автоматически.

## Что уже реализовано

- ввод URL подписки прямо в UI плагина;
- резервный ручной импорт `YAML`;
- обновление подписки;
- запуск и остановка `mihomo`;
- `TUN`-режим для системного VPN;
- отображение групп и нод;
- проверка доступности серверов;
- выбор рекомендуемой ноды;
- ручное переключение между серверами.

## Сборка проекта локально

Требования:

- `Node.js 20+`
- `npm`
- `Python 3`

Команды:

```bash
npm install
npm run build
python -m py_compile main.py
```

После сборки фронтенд будет лежать в `dist/`.

## Какие файлы нужны для плагина

Минимально нужны:

- `dist/index.js`
- `package.json`
- `plugin.json`
- `main.py`

Дополнительно:

- `bin/mihomo` если захочешь поставлять бинарник вместе с плагином, а не скачивать его при первом запуске

## Установка на Steam Deck

Общий порядок такой:

1. Собери проект.
2. Подготовь папку плагина с файлами `dist`, `package.json`, `plugin.json`, `main.py`.
3. При желании добавь `bin/mihomo`.
4. Скопируй плагин в каталог плагинов Decky на Steam Deck.
5. Перезапусти `Decky Loader` или сам `Steam`.

Если будешь выкладывать проект на GitHub, не добавляй в репозиторий свои реальные:

- ссылки подписки;
- `YAML` с рабочими ключами;
- `uuid`;
- `reality public-key` / `short-id`;
- любые приватные токены.

## Как пользоваться в игровом режиме

1. Открой плагин в `Decky Loader`.
2. Вставь ссылку на подписку в поле URL.
3. Нажми `Сохранить и обновить`.
4. Дождись, пока профиль загрузится.
5. Выбери группу нод.
6. Нажми `Проверить серверы`, чтобы получить задержку.
7. Нажми `Найти лучшую`, если хочешь автоматический выбор самой живой ноды.
8. Либо выбери нужную ноду вручную.
9. Нажми `Подключить`, чтобы включить VPN в `TUN`-режиме.

Если ссылка подписки не импортируется напрямую, можно раскрыть блок резервного импорта и вставить `YAML` вручную.

## Безопасность

- Плагин не вшивает твою подписку в код репозитория.
- Подписка сохраняется локально на устройстве после добавления через интерфейс.
- Публиковать реальные конфиги в открытый GitHub-репозиторий нельзя.

## Ограничения и нюансы

- Проект написан под `Steam Deck / SteamOS`, но из этого Windows-окружения я не мог полноценно проверить runtime на самой консоли.
- Для первого запуска нужен интернет, если `mihomo` не приложен в `bin/`.
- Проверка серверов сейчас идет через `mihomo controller API`.
- Для health-check используется `https://cp.cloudflare.com/generate_204`.
- Если провайдер отдает не `Clash/Mihomo YAML`, а другой формат подписки, надежнее использовать ручной импорт экспортированного `YAML`.

## Структура проекта

- [main.py](./main.py) — backend Decky-плагина, управление подпиской, `mihomo` и проверкой нод
- [src/index.tsx](./src/index.tsx) — интерфейс плагина для игрового режима
- [plugin.json](./plugin.json) — метаданные Decky-плагина
- [package.json](./package.json) — зависимости и команды сборки

## Примечание

Репозиторий начинался с официального шаблона `Decky plugin template`, но примерные backend-файлы шаблона здесь больше не используются: логика плагина перенесена в `Python backend + TypeScript UI`.
